# CLAUDE.md — project conventions for Claude Code

Read this before making changes. It is the source of truth for how this repo is worked on.

## What this is

Melanated Online — an editorial site (Fashion, Beauty, Wellness, Business, Community) for a client, built as a production-quality portfolio piece. Next.js 16 App Router + Payload CMS 3 + Postgres + Tailwind 4, deployed to Vercel. See `README.md` for architecture and `docs/adr/` for decisions.

## Commands

```bash
pnpm dev              # dev server (needs DATABASE_URL + PAYLOAD_SECRET in .env)
pnpm check            # lint + typecheck + prettier — must pass before any commit
pnpm test:int         # unit tests (Vitest)
pnpm test:e2e         # Playwright (needs a running Postgres)
pnpm generate:types   # after editing any collection/global
pnpm migrate:create   # after editing any collection/global — commit the migration
pnpm seed             # categories + first admin
```

## Rules

- **Run `pnpm check` before every commit.** Never commit with lint, type or format errors.
- **Schema change = types + migration.** Editing `src/collections/*`, `src/globals/*` or `src/fields/*` requires `pnpm generate:types` and `pnpm migrate:create` in the same commit.
- **All frontend data reads go through `src/lib/queries.ts`** so caching and tags stay in one place. Never call `getPayload` from a page or component.
- **Every cached query has a tag** from `CACHE_TAGS` in `src/hooks/revalidate.ts`, and the matching CMS hook revalidates it.
- **Scripts that write via the Local API** must pass `context: { disableRevalidate: true }` (they run outside Next).
- **Design tokens live in `src/app/(frontend)/globals.css`** under `@theme`. Don't hard-code hex colours in components; add a token.
- **Accessibility is not optional:** every image has `alt`, every interactive element is reachable by keyboard, tap targets ≥ 44px, colour contrast AA (butter/caramel only on espresso, or as eyebrows).
- **Do not edit** `src/app/(payload)/**` (generated by Payload) or `src/payload-types.ts` (generated).
- **Don't add dependencies** without a one-line justification in the commit message.
- Prefer server components; add `'use client'` only when the component needs state or browser APIs.

## Commit messages

Conventional Commits, imperative mood, scoped where useful:

```
feat(cms): add scheduled publishing to posts
fix(site): fall back to category posts when relatedPosts is empty
chore(ci): run Playwright against a production build
docs(adr): record choice of Vercel Blob for media
```

One logical change per commit. Reference the ADR when a commit implements a decision.

## When asked to "review" or "audit"

Check, in this order: access control (can an author do something only an admin should?), cache invalidation (does every write revalidate the right tag?), accessibility, mobile layout at 375px, then code style.

## Client context (don't ship without confirming)

Open questions tracked in `README.md` → "Open questions for the client": brand name, final categories, light vs dark base, author publish rights, newsletter provider, WhatsApp/Instagram links, domain.
